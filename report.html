〇一最核心结论：封号分两条独立轨道

很多人把「撞到周限额被限流」误当成「封号」。Max 20x 重度使用本身只会被限流（throttle），不是封号——封号挂在使用方式上（第三方工具 / 共享 / 转售 / 区域 / 支付信号），而不是用量大。

〔表一〕两条独立轨道
轨道性质后果可否恢复
Token 级封锁订阅 OAuth token 在非官方客户端被服务器拒收（2026-01-09 起）账号没被封，只是该凭证在官方 Claude Code 之外失效换回官方客户端即恢复
账号级封禁“suspicious signals” 滥用分类器判定的封号账号被禁用，余额不退需申诉，翻盘率仅 ~3.3%

〇二封号审查因素（按相关度排序）

A · 反套利类 —— Max 20x 用户真正的雷区（官方主动严打）

F-01把订阅 OAuth token 用到任何非官方客户端官方

2026 年最大一波、最高发。官方明文：“Using OAuth tokens obtained through Claude Free, Pro, or Max accounts in any other product, tool, or service — including the Agent SDK — is not permitted.” 连 Anthropic 自家 Agent SDK 都算违规。波及 OpenClaw/Clawdbot、OpenCode、Cline、Roo Code、deer-flow 及各类 claude setup-token / CLAUDE_CODE_OAUTH_TOKEN 导出桥。时间线：2026-01-09 服务器静默封锁 → 2/17-20 写入 ToS → 4/4 全面计费切割。

检测方式多源：不靠 UA/TLS/client-id（可伪造），而是分析请求载荷——系统提示结构 + tool schema 形状，识别是否真·Claude Code。

F-02账号共享 / 转售 / 拼车官方

Anthropic 明说周限额就是为打击 “account sharing and reselling”。Max 5x/20x 是单用户套餐；一份订阅多人/团队用、或拆分转售（中文圈「拼车/合租」，Max 20x 黑产 3-7 折拆卖）= 直接违规。

F-03把订阅当 API 跑自动化（token 套利）官方

ToS §3.7 禁止 “automated or non-human means” 访问（除非走 API key）。平面费率套餐被 agent harness 7×24 跑，$200 订阅烧掉 $1,000–$5,000 等价算力。→ 2026-06-15 起这类用量被切到独立 “Agent SDK credit” 池按 API 价计费，替代了过去「连额度一起封」的做法。

F-04headless claude -p / CI/CD / 后台守护挂在订阅上官方

GitHub Actions、批处理、无人值守自动化走订阅 OAuth 属违规。

F-05多账号绕过限额（limit-hopping）/ 封后开新号多源

⚠️矛盾点：Anthropic 员工 Thariq Shihipar 明说「持有多个 Max 账号本身不违规」，但分类器仍反复误封多账号用户。真正的违规是用多账号轮换绕限额和封后重注册。检测靠支付卡/IP/设备指纹做关联（连坐）。

B · 支付 / 账单风险信号（常在「充值/升级瞬间」触发复审）

F-06代充 / 第三方充值（recharge / top-up）多源

中文圈列为「几乎必封」档：付款人身份与账号持有人永远对不上，欺诈检测必标记。

F-07高风险 / 虚拟 / 预付卡多源

卡 BIN 国 ≠ 账单国 ≠ IP 国时触发；Stripe 风控可致即时封。

F-08拒付 / chargeback官方

争议处理期间无法退款，且判例显示会导致卡+身份被永久拉黑（#47046）。

F-09低价区套利 / 区域不一致多源

VPN 去尼日利亚/土耳其/阿根廷等低价区订阅；中文「防封」指南强调 IP国=手机国=邮箱区=卡账单地「四位一体」。

F-10大额 / 快速升级事件多源

多起「升级 Max 20x 后几秒到几小时被封」（#37057/#60923/#45936）；付款事件似乎会触发对账号历史的全面复审。

F-11礼品订阅 / 赠送 Max多源

兑换礼品即被封的边缘案例簇（#41252/#45335），礼品/兑换流撞上自动复审 + Stripe 折算边缘。

C · 网络 / 区域 / 设备信号

F-12从不支持 / 受制裁区域访问官方

中国大陆、香港、澳门、俄、白俄、伊朗、朝、古、克里米亚等；2025-09 起还禁中国控股 >50% 的实体。⚠️对位于中国的用户是系统性高危。

F-13VPN / 代理「坏邻居」IP 连坐多源

商业 VPN 出口（ProtonVPN/NordVPN 被点名）被预标记；同 IP 别人违规你遭殃。

F-14数据中心 / VPS IP vs 住宅 IP多源

AWS/Azure/Hetzner 段被当「非人类」。⚠️矛盾点：固定 VPS IP 的稳定用户反而比频繁换 VPN 的少被封——IP 一致性/信誉 > 是否数据中心。

F-15「不可能的旅行」多源

几分钟内跨国跳 IP，立即触发反滥用告警。

F-16设备 / 浏览器指纹 + Cookie 多账号关联传闻

来源多是指纹浏览器厂商软文，可信度打折。

F-17中国用户专项环境检测（已承认并移除）官方

最硬的实测信号。Claude Code v2.1.91–196 会读系统时区（Asia/Shanghai、Urumqi）、比对代理域名里的中国云/AI 实验室关键词（百度/阿里/字节/deepseek/moonshot…），并用隐写术（把撇号 U+0027 换成视觉相同的 U+2019 等）把 3-bit 标记藏进系统提示回传。Anthropic 承认为「反代充/反蒸馏实验」，v2.1.197（7/1）移除。⚠️这意味着身处中国的正常 Max 用户即使 IP 干净也风险偏高（判据是时区+中转域名，非 IP 段，「杭州 IP 段」说法已被证伪）。

D · 使用政策 / 内容违规（对纯编码用户基本不相关，但确实存在）

F-18AUP 三层结构（通用 / 高危 / 硬性禁止）官方

硬性禁止含 CSAM、恶意软件、欺诈、武器、选举行贿等，触即封；2025-09 更新细化网络安全禁令（勒索软件/EDR绕过/C2/数据外泄）。独立分析约 69 类禁止用途。

F-19未满 18 岁官方

确认未成年即封；自动分类器扫对话判年龄，误封成年人走 Yoti 年龄验证恢复。

F-20模型蒸馏 / 竞争性训练官方

用输出训练竞品模型。旗舰案例：2026-02 披露 MiniMax(~13M)/Moonshot(~3.4M)/DeepSeek(~150K+) 用 ~24,000 假账号蒸馏；6 月又指控阿里 Qwen ~25,000 假账号 28.8M 次交互，升级到国会+出口管制层面。

〇三审查 / 执行机制（怎么被抓、怎么申诉）

〔表二〕审查与执行机制
环节可信度说明
执行阶梯官方警告 → 累计阈值 → 暂停 → 终止。但对消费者常无预警直接封。
检测官方多源AI 分类器扫内容 + CSAM 哈希比对 + 跨账号关联调查 + 实时阻断；绝大多数封禁是自动触发，人工只在申诉或严重案例介入。
两条封号文案多源「suspicious signals associated with the account」= 环境/账号信号分支（VPN/区域/支付/多账号）；「automatic review of your recent activities」= 内容/行为分支。两者都导向同一申诉表。
申诉官方claude.ai 用被封账号登录填申诉表；警告异议发 usersafety@anthropic.com。Transparency Hub：2025 下半年封 145 万账号、5.2 万申诉、仅 ~1700 翻盘（≈3.3%）。
误封真实存在官方Thariq Shihipar 承认 2026-01 收紧后有 “regular subscription accounts” 被误封并恢复；甚至有自家 VS Code 扩展后台活动（#41046）、自动生成的 claude-bridge 子进程（#47046）把普通用户坑封。
身份核验官方2026-07-08 起对部分被标记用户要 ID+自拍（Persona 做 KYC、Yoti 做年龄），不通过=事实封号。

〇四给 Max 20x 用户的避险要点

  1. 只用官方客户端（Claude Code CLI / claude.ai / 桌面 / Cowork），别把订阅 token 喂给任何第三方——哪怕自家 Agent SDK。
  2. 一份订阅一个人用，别拼车别转售别团队共登。
  3. 自动化 / CI 走 API key 付费，别挂订阅。
  4. 别碰代充 / 虚拟卡 / 低价区，账单信息前后一致，别轻易拒付。
  5. 身处中国 = 系统性高危（政策 + 时区/中转检测），这是客观风险不是操作能完全规避的。
  6. 用量再大也只是被限流；但「多 IP 并发 + 异常吞吐 + 信号叠加」会被分类器误判——误封后申诉翻盘率仅 ~3%，所以前置规避远比事后申诉重要。

本报告由 15 个并行调研 Agent（官方政策 / OAuth-第三方 / 用量滥用 / 支付账单 / VPN-区域 / 社区报告 / 执行机制 / 检测信号 + 完整性批评家 + 6 个补漏方向）汇总而成，去重后按可信度分级。所有结论以 Anthropic 官方文档与实际执行为准。
